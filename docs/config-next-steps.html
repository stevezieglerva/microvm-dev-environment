Next steps

  1. Keep local and shared SAM config aligned

    When creating or updating the ignored local samconfig.toml, retain tags = "Type=\"ai-vm\"" under [default.deploy.parameters]. Keep the same setting in samconfig.toml.example so fresh checkouts inherit it.

    Done when: a new local config copied from the example includes the tag.

  2. Confirm repeat deploy behavior

    Run the normal deploy flow against the intended AWS profile and verify the CloudFormation stack still reports Type=ai-vm after an update. The script passes --tags explicitly, so its behavior does not depend only on local SAM config.

    Done when: a routine update completes and the stack tag remains present.

  3. Make first-deploy configuration unambiguous

    Reconcile the README bootstrap sequence with deploy.sh's prerequisite check. The script expects stack outputs for the artifact bucket and gateway role before its full deploy; document the exact first-time commands and required parameters in one canonical sequence.

    Done when: a new operator can bootstrap from a clean account without guessing which deploy command to run first.

  4. Review deployment identity and permissions

    Document the expected AWS account/profile and the permissions required by the full deploy, including CloudFormation resource tagging. Review any temporary bootstrap permissions and reduce or remove them when they are no longer needed.

    Done when: the deploy guide names the target identity and the retained policy is least-privilege for ongoing operations.

  5. Decide whether resources need the same tag

    The requested tag is set on the CloudFormation stack. Check the resources and cost reports that matter to confirm whether stack-level tag propagation is sufficient, or whether selected template resources need explicit tags.

    Done when: the tagging scope is documented and verified against the intended inventory or cost-allocation use.
Before another deployment: confirm the AWS caller identity and account shown by deploy.sh. The script follows the active AWS profile/environment and does not select an account on its own.
